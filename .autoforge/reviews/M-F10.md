## Findings

1. **[OK] All counts verified**: 109/109 unit, 32/32 e2e GO; drill paths covered end-to-end (preview, scoring, session flag).
2. **[OK] ADR-18 honored**: single-view drill, varying preview width, fixed anchor, lookahead reuse, `drill:'span'` persisted, dashboard/metrics untouched.
3. **[OK] Copy gate green** with the scoping stated above.
4. **[ANOMALY — explained, not a submission bug]** `total:5` is **not** five recognition submissions. Chain: (a) only one increment site, guarded — `player-view.js:179-183` (`if (!recognitionPending) return; … recognitionTotal += 1`); (b) the harness dispatches exactly one submit (`e2e-walkthrough.mjs:365-370`) and contains no key/`Input.` dispatch (grep: none); (c) at quiz save, pre-existing code overwrites the session with quiz counts — `app.js:293-301` (`correct: result.correct, total: result.total`), quiz is `n: 5` (`app.js:152`) answered with five wrong `'zzz'` values (`e2e-walkthrough.mjs:392-393`) → `{correct:0,total:5}`; (d) the harness reads sessions **after** quiz submit (`:400-405`). So recognition `1` was overwritten by quiz `5`. Consequence: the e2e assertion `drillSession.total >= 1` (`:407`) is vacuous for drill sessions — it would pass even if recognition counting were broken. Not a runtime defect, but the check does not test what its name claims.
5. **[Note] Preview "pencil" styling absent**: `player-view.js:151` comment says "in pencil", but no `.rsvp-preview` rule exists anywhere (`grep -rn rsvp-preview --include='*.css' --include='*.html'` → empty); preview renders as plain right-column text, visually merged with the sentence tail. Cosmetic vs ADR-18 intent.
6. **[Note] Recognition counts are not durable**: for drill sessions, persisted `correct/total` mean quiz counts once the quiz is saved (finding 4c). If recognition stats must be readable later, persist under distinct fields or skip the overwrite when `drill === 'span'`. Also, drill mode has no unit test (`grep -rln drill test/` → none); only the lookahead helper is unit-tested (`test/player.test.js:44-57`).

## Required changes
None blocking. Suggested follow-ups (non-blocking): fix the e2e drill-count assertion to read the session before quiz save (or assert in-page `recognition N/M` state); style `.rsvp-preview` or drop the "pencil" comment; decide whether recognition counts should survive quiz save.

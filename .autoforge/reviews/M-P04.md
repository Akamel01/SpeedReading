## Verdict: REJECTED

Neither library implements the frozen §13 interface. Every contract function is missing; both modules expose a different, invented API; the catalog is 3 placeholder ids vs ADR-24's 6; the tests are green only because they assert the invented API (and in places re-derive their expectation from the implementation's own formula). This is not a fixable diff on top of the existing code — it is a rewrite against the contract. The one conforming artifact is `RECORD_IDS` in `records.js:4-15`, whose 10 ids match the plan list exactly.

## Ranked findings

### Blockers
1. **B1 — `challenges.js` does not implement the §13 interface at all** (`src/lib/challenges.js:5-9,28-56`). Fix: delete `CHALLENGES`/`createChallenges`/default; implement pure `challengeFor(now, period)` → `{ id, period, title, description, target, unit, xp }` and `challengeProgress({ sessions, quizzes }, { now })` → `{ daily, weekly }` with `ChallengeState = { id, period, periodStart, periodEnd, title, target, current, pct:0..100, complete, xp }`. No stored/mutable state; no ambient `new Date()`.
2. **B2 — challenge catalog is 6/6 wrong** (`src/lib/challenges.js:5-9`). Fix: exact ADR-24 entries: daily rotate `daySerial % 3` = `d-read`/"Read 500 words today"/500 words/50xp · `d-comprehend`/"Finish a quiz with at least 60% today"/1 scored session/50xp · `d-focus`/"Read actively for 10 minutes today"/600,000 ms/50xp; weekly Monday-start rotate `weekIndex % 3` = `w-volume`/"Read 5,000 words this week"/150xp · `w-days`/"Read on 4 days this week"/150xp · `w-comprehend`/"Score 70% or more on 3 quizzes this week"/150xp.
3. **B3 — weekly rotation, period boundaries, monotonic completed periods absent** (`src/lib/challenges.js:31-41`). Fix: `daySerial`/`weekIndex` from local date parts (`getFullYear/Month/Date`, Monday-start week), `localDayStart`/`localWeekStart` for `periodStart`/`periodEnd`; derive `current` from injected `{sessions,quizzes}` so reset needs no UI; completed periods immutable.
4. **B4 — `records.js` does not implement the §13 interface at all** (`src/lib/records.js:4-57`). Fix: delete `getCatalog`/`rankRecords`/`drillRankRecords`/`sanitizeInput`/default; implement `personalRecords(sessions, { dayMap })` → `[{ id, label, value, unit, at, sessionId?, day?, ties }]` and `recordImprovements(sessions, { dayMap })` → `[{ id, at, value, previous, sessionId? }]` (strict improvement only), ties → earliest `at`.
5. **B5 — drill-exclusion semantics inverted/invented** (`src/lib/records.js:39-44`). Fix: drill sessions (`drill:'span'`) excluded from `fastest-wpm`, `best-comprehension`, `best-combined`, and `fastest-wpm-chunk-1/-2/-3`; included in `longest-session`; scored records require comprehension ≥60% (combined = wpm × pct/100, scored); `best-comprehension` per ADR-24.

### Majors
6. **M1 — tests assert the invented API and cannot catch contract drift** (`test/challenges.test.js:13-14,52-53` re-derive expected rotation from the implementation's own formula; `test/records.test.js` tests ranking helpers). Fix: rewrite tests to call the §13 signatures with fixed injected `now` and ADR-24 tables; assert exact ids/titles/targets/units/xp, `pct` 0..100, earliest-`at` ties, strict improvement, drill exclusions, Monday-start week boundary, DST fixture with cross-boundary rotation.
7. **M2 — execution report is inaccurate/stale** (`.autoforge/execution/M-P04.md:10-13`). Fix: report only verifiable outputs; remove garbled line 13; state test counts and the actual interface; a re-queue report must list the §13 functions with one-line evidence each.

### Minors
8. **m1 — malformed input throws**: `createChallenges(null)` (`challenges.js:29`) and `rankRecords(null)` (`records.js:29`). Contract requires no-throw; the rewrite must coerce non-objects to `{}`.
9. **m2 — `setProgress(NaN)` poisons stored progress to `NaN`** (`challenges.js:51`). Non-issue after rewrite (no stored state), but any surviving numeric path must guard non-finite input.
10. **m3 — extra invented public exports** (6 across the two files) violate the §13 freeze surface. Rewrite exports exactly `challengeFor`, `challengeProgress` and `personalRecords`, `recordImprovements`.
11. **m4 — DST "fixture" is a regex-only assertion** (`test/challenges.test.js:38-42`), not a determinism check; covered by M1's rewrite.

## Findings (ranked)

### F1 — BLOCKER: stale streak reported as alive (`src/lib/streak.js:63-84`)
`baseDayKey = activeToday ? todayKey : lastDayKey` (line 65) never checks the yesterday-grace window. When the last active day is older than yesterday, `current` is computed as the length of that dead historical run (probe: 3 instead of 0). This violates the ticket's "current streak with yesterday-grace" and the injected-`today` determinism requirement; every downstream consumer (`streakCard`, `streakXp`, achievements `streak-3/7/30/100`) would show a live streak after weeks of inactivity.

Fix (after line 65):
```js
let baseDayKey = activeToday ? todayKey : lastDayKey;
if (!activeToday && typeof todayKey === 'string') {
  const y = toDateFromKey(todayKey);
  if (y) {
    y.setDate(y.getDate() - 1);
    if (dayKeyFromDate(y) !== lastDayKey) baseDayKey = null; // last activity older than yesterday → broken
  }
}
```
(`baseDayKey = null` flows into the existing `if (baseDayKey)` guard, yielding `current: 0`.)

### F2 — MAJOR: `longest` is DST-unsafe (`src/lib/streak.js:96`)
`(date - prevDate) / 86400000 === 1` compares local midnights with a fixed-ms divisor; a 23h (spring-forward) or 25h (fall-back) day fails the `=== 1` test and resets the run. Probe in `America/New_York` on 2026-03-07..09 gives `longest: 2` while `current: 3` — the two computations disagree about the same data. The repo's own standard (ADR-24 / M-G03) demands local date-part arithmetic, never fixed-ms, and the ticket says "timezone-correct without a timezone library".

Minimal fix at line 96: `if (Math.round((date - prevDate) / 86400000) === 1) run += 1;` — or, matching the `current` loop, compare `dayKeyFromDate(prevDate + 1 day) === k`.

### F3 — MAJOR: contract-required test cases missing (`test/streak.test.js`)
Only 6 tests exist; the ticket (line 11) and plan §M-G02 acceptance require empty; same-day=1; consecutive; gap; yesterday-only; **month AND year** boundary; **injected today**; malformed skipped. Missing:
- **year boundary** (e.g. 2026-12-31 + 2027-01-01, today 2027-01-01 → current/longest 2). The existing test only covers a month boundary (lines 71-83).
- **injected-today stale** (F1's case: 2026-01-01..03, today 2026-01-10 → current 0, longest 3) — would have caught F1.
- **malformed skipped** — no test exercises `dayMap([null, {}, {startedAt:'x'}, {startedAt:NaN}, ...])`; the execution report's "robust handling of malformed sessions" is an untested claim.
- (optional regression) a DST case, pinned with `TZ=America/New_York`, for F2.

### F4 — MINOR: `today` accepted only as a `'YYYY-MM-DD'` string (`src/lib/streak.js:64`)
A number/Date `today` (the shape `achievements.js:48` uses) silently yields `activeToday: false` and skips the grace check, i.e. wrong `current` rather than an error. Freeze (ADR §13) says `streakStats(dayMap, today)` without a type; downstream M-G06/M-G04 will call it. Either normalize (`typeof today === 'number' ? dayKey(today) : today`) or document the string-only contract in a one-line comment and in the freeze.

### F5 — MINOR: `toDateFromKey` lacks range validation (`src/lib/streak.js:14-18`)
`parseInt` + `new Date(y, m-1, d)` silently rolls over (`'2026-13-45'` → 2027-02-14). Only reachable via caller-built maps (module-produced keys are always valid), so low severity; a bounds check (`m 1..12`, `d 1..31`, round-trip `dayKeyFromDate` equality) would close it.

### F6 — MINOR: dead guard (`src/lib/streak.js:69-70`)
`baseDayKey` always comes from map keys, so `dayMapObj.has(baseDayKey)` is always true; the inner `if` adds a branch that can never be false. Delete it when applying F1.

### 2. Contract §8 / ADR-13

Actual code (`src/lib/metrics.js:19-37`):
```js
export function activeMs(events) {
  if (!Array.isArray(events) || events.length <= 1) return 0;
  let sum = 0;
  for (let i = 1; i < events.length; i++) {
    const prev = events[i - 1];
    const cur = events[i];
    const atPrev = prev?.at;
    const atCur = cur?.at;
    const expPrev = prev?.expectedMs;
    if (typeof atPrev !== 'number' || typeof atCur !== 'number' || typeof expPrev !== 'number') {
      continue;
    }
    const gap = atCur - atPrev;
    const cap = expPrev * 4 + 250;
    const contribution = Math.min(gap, cap);
    if (Number.isFinite(contribution)) sum += contribution;
  }
  return sum;
}
```
Pure (no I/O, no mutation of `events`), cap uses **previous** event's `expectedMs`, empty/single → 0. Matches contract.

## Findings
1. **(note, non-blocking)** Negative `gap` (out-of-order timestamps) yields a negative contribution, e.g. probe `got=-500`; `activeMs` can return a negative number. `app.js:120` `active > 0` guard means no user-facing effect (falls back to `wallMs`). No contract clause covers it; leave unless a caller consumes the raw value.
2. **(note, non-blocking)** A single malformed `at` (NaN) drops both adjacent gaps, not just one (pair with NaN skipped, following pair's `prev` is the NaN event). Probe: `NaN at skipped: got=0` for a 3-event sequence whose only usable span was 0→300. "Skipped" semantics match the stated check; no data corruption, but worth knowing if lossy-event tolerance ever matters.
3. **(note)** Unit tests for `activeMs` cover empty/single/gaps/cap but not NaN/undefined/frozen-input for this function specifically (purity test at `test/metrics.test.js:75-77` targets `summarize`). Behavior verified by this review's probes; optional hardening if these edges are considered contract-relevant.
4. Contract, cap values (`expectedMs*4+250`), previous-event cap semantics, and call-site equivalence all verified; no regression in full suite (108/108) and E2E (25/25).

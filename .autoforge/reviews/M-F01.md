# Review — M-F01 Chapter picker

Reviewer: autoforge-reviewer (read-only). Date: 2026-09-23.
Contract: `.scratch/speedreading-followups/issues/01-chapter-picker.md` + ADR-11 (`decisions.md:88-91`).
Scope reviewed: `src/app.js` (openText, recordSession, quiz onSave), `src/ui/library.js` (chapter select), `.autoforge/validation/e2e-walkthrough.mjs` chapter steps.

## Verdict: CHANGES_REQUIRED

Session attribution, chapter selection, fallback behavior, and all walkthrough gates pass. One contract requirement is unmet: the persisted quiz record does not carry `chapterIndex`, contradicting ADR-11 ("Quiz += `chapterIndex`", `decisions.md:90`) and the issue acceptance "Session row and quiz associate with the chapter actually read" (`01-chapter-picker.md:41`).

### 3. ADR-11 semantics (code quotes)

- Explicit index wins; substantial-chapter fallback preserved — `src/app.js:93-95`:
  ```js
  const requested = Number.isInteger(chapterIndex) && text.chapters[chapterIndex] ? text.chapters[chapterIndex] : null;
  currentChapter = requested ?? text.chapters.find((c) => (c.wordCount ?? 0) >= 50) ?? text.chapters[0];
  currentChapterIndex = text.chapters.indexOf(currentChapter);
  ```
- Session attribution — `src/app.js:130-133`: `textId: currentText.id,` + `chapterIndex: currentChapterIndex, chapterTitle: currentChapter.title,`. Quiz generation stays chapter-scoped (`app.js:149`: `generateQuiz(currentChapter.text, ...)`).
- `textId` remains grouping key; dashboard untouched: `src/ui/dashboard.js` has zero chapter references; `render({sessions})` → `summarize(sessions)` with no filtering (`dashboard.js:114-120`). Store untouched (`src/lib/store.js` unmodified in diff).
- **Gap — quiz record drops `chapterIndex`.** `recordSession` passes it to the view (`app.js:153`: `chapterIndex: currentChapterIndex,`), and `quiz-view.js:150,161` spreads it back (`onSave?.({ ...quiz, ... })`), but the record written to the store reselects fields and omits it — `src/app.js:281-288`:
  ```js
  await store.put('quizzes', {
    id: editedQuiz.id,
    textId: editedQuiz.textId,
    createdAt: editedQuiz.createdAt,
    seed: editedQuiz.seed,
    questions: editedQuiz.questions,
    edited: editedQuiz.edited === true,
  });
  ```
  Grep confirms: `grep -rn chapterIndex src/` returns only `app.js:93,132,153` — no store write. No e2e or unit assertion covers quiz attribution (walkthrough reads `sessions` only, `e2e-walkthrough.mjs:291-296`). This is M-F01's own acceptance criterion and its own file (`app.js`), not a downstream module's.

### 4. Adversarial probes (code-read; all file references verified)

- **1 chapter → no select.** `src/ui/library.js:163`: `if (Array.isArray(t.chapters) && t.chapters.length > 1) {` — single-chapter items render Open only, and `chapterSelect` stays null so `requested` is null (`library.js:181`), preserving prior default-pick behavior. PASS.
- **Invalid index → fallback.** `app.js:93` requires `text.chapters[chapterIndex]` to be truthy, so 99, -1, non-integers, and NaN all yield `requested = null` → fallback chain runs. PASS.
- **Missing `chapters` array.** Library path safe (`Array.isArray` guard, no select). Open path is not: `app.js:85` `if (!text || !text.chapters.length)` throws `TypeError` on `chapters === undefined`, so the click handler rejects and the alert/route never runs. Not introduced by M-F01 (identical check at `git show 989fe8b:src/app.js:83`) and not reachable through UI imports (every `ingest`/paste/URL path returns a non-empty `chapters` array; export/import round-trips the same shape). Recorded as a note, not a blocker.
- **Dashboard "Start session" after a chapter pick reopens the default chapter.** `app.js:315`: `if (textId) openText(textId);` — no index argument, so the 50+-word fallback applies again. Acceptable: chapter memory across visits is explicitly out of scope (`01-chapter-picker.md:46` "Bookmarks or resume-position memory across visits"), and ADR-11 deliberately keeps chapter state ephemeral in `app.js`.
- **a11y.** Select is a native control with `aria-label` (`library.js:166`) and is reachable by keyboard; global `:focus-visible` rule exists (`styles/app.css:18`). Minor: `.library-chapter` has no CSS rule of its own (functional, unstyled beyond UA defaults).

### 5. Other notes

- ADR-11 also says records lacking chapter fields "render 'unknown'". No surface renders a chapter for sessions at all — the dashboard table headers are `['Date','Kind','Chunk','WPM','Comprehension']` (`dashboard.js`) — so the requirement is vacuous rather than violated; "never filtered" is what actually matters and the legacy-row walkthrough step proves it. Flag only if a chapter column is intended in a later module.
- Scope is clean: M-F01 diff is confined to `app.js` + `library.js`; metrics/text/quiz-view changes in the worktree belong to sibling modules.

3. Re-run `node .autoforge/validation/e2e-walkthrough.mjs` (expect 28/28 with the added assertion) and `node --test` (expect 108/108).

Non-blocking, optional: guard `openText` with `Array.isArray(text.chapters)` before `.length`; style `.library-chapter` in `styles/app.css`.

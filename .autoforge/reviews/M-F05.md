## Findings

1. **[minor, test quality]** The dismiss assertion is vacuous. It dispatches `{}` (line 97), which `store.importAll` rejects on `schemaVersion !== 1` (`store.js:89`) even when confirm is true. So `countAfter === countBefore` holds whether or not the `window.confirm` gate exists — the test cannot detect removal of `app.js:335`. Fix: use a valid snapshot (`{ schemaVersion: 1, texts: [one valid text], quizzes: [], sessions: [], settings: [] }`) and assert the library still shows the pre-existing item, plus zero alerts.
2. **[minor, test quality]** "Data intact" is proven by item count only (1 → 1), not by content identity. A same-count overwrite would pass. Cheapest strengthening: capture `textContent` of the library item before/after and compare.
3. **[info, fidelity]** Accept-path import dispatches on `#view-dashboard .dashboard-import` while the dashboard view is hidden (querySelector works on hidden DOM); the handler and file-input path are real, but a human click-through is not simulated. Acceptable for a harness; no action required.
4. **[info, positive]** Export coverage relies on the dashboard button; the library "Export" button (`library.js:27-31`) is not separately exercised. Same `onExport: exportData` callback in both (`app.js:249`, `app.js:315`), so no behavioral gap.
5. **[info]** `scripts/` is untracked (`?? scripts/`). If this harness is meant to be part of the repo's validation surface, it needs a commit; otherwise it is at risk of being lost/ignored. Not a code defect.

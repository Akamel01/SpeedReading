## Findings (ranked)

### BLOCKER 1 — `simulate-corrupt` is a production URL backdoor that destroys user data
`src/app.js:56-67`: `boot()` reads the URL and, on `?simulate-corrupt`, calls `indexedDB.deleteDatabase('speedread')` then throws. `store.js:14` confirms `DB_NAME = 'speedread'` — the live DB. Verified live: import a text, visit `index.html?simulate-corrupt`, return to `index.html` → 0 library items. This is a hidden test hook in production code (not the plan's mechanism, which requires the simulation to live in the harness: CDP DB deletion or stubbed `openStore` rejection), and the harness never uses the param (`grep simulate-corrupt` matches only `src/app.js` and the worker report). A single URL click silently wipes the user's library. Also observed once: after visiting the param, the next plain load stalled >12 s while the pending `deleteDatabase` blocked `openStore` (transient, not reproduced deterministically).

Fix: delete `src/app.js:56-67` entirely. Keep the `boot().catch` banner (`src/app.js:413-428`) — it already handles real failures (verified with a stubbed `IDBFactory.prototype.open`). Implement the simulation in `.autoforge/validation/e2e-walkthrough.mjs` via `Page.addScriptToEvaluateOnNewDocument` (stub `indexedDB.open` to throw) or by deleting the DB through CDP before boot; name it in the module report.

### BLOCKER 2 — mobile bottom tab bar never applies; header stays sticky at top
`styles/app.css:11-17` sets `position: fixed; bottom: 0; top: auto` under `@media (max-width: 767px)`, but the pre-existing S1 material block at `styles/app.css:75-77` (`header { position: sticky; top: 0; }`, same specificity, later in source) wins on `position`/`top`, and `styles/app.css:79-83` wins on padding/background/border. Verified by CDP at 375px: `position: sticky, top: 0px`, header at the top of the viewport. Acceptance "bottom tabs at 375px (≥44px targets)" fails (targets themselves are 44px ✓, same DOM/order ✓).

Fix: place the mobile override after the material block (e.g. move the `@media (max-width:767px)` header/nav rules below `styles/app.css:84`, or repeat them at the end of the S1 section). Include `padding-bottom: calc(0.25rem + env(safe-area-inset-bottom))` — safe-area padding is named in the plan objective and is currently absent. While there, fix `#app` bottom spacing: `styles/app.css:30` (`padding-bottom: 60px`) never applies because `index.html:27` has inline `style="padding:1rem"`; use `padding-bottom: calc(<bar height> + env(safe-area-inset-bottom))` on the mobile path or drop the dead rule.

Fix (owner: M-G03, not this module): restore `target = 10`, update the fixture to 10 qualifying sessions, keep the catalog text. M-P02's worker must not edit gamify libs; the M-P02 report's claim "no other files touched" is false.

The static readable copy in `index.html:44` is overwritten. ADR-21 requires "readable" copy. Fix: always show the static user-facing message; keep the technical detail in `console.error` (`src/app.js:414` already logs it).

## Agent Brief

**Category:** enhancement
**Summary:** Add a quiz authoring mode that edits expected answers, kept strictly separate from the answering flow where expected answers stay hidden.

**Current behavior:**
The quiz view shows empty inputs for the reader's answers and saves them for scoring against the generator's expectations. There is no way to correct a bad auto-generated blank or distractor; the quiz record carries an `edited` flag that is always false.

**Desired behavior:**
From a quiz (before taking it, or from the library entry), the owner can open an authoring view listing each generated question with its sentence, current expected answer, and accepted alternatives, all editable. Saving persists the edited quiz with `edited: true`. The answering flow is unchanged: inputs start empty, expected answers are never rendered into the answering DOM.

**Key interfaces:**
- The quiz record (id, text id, seed, questions with sentence/answer/accepted/candidates, edited flag): authoring writes it, answering only reads expectations and writes the reader's answers
- The scoring function comparing normalized reader answers against normalized expectations: reused unchanged
- The existing quiz-start/save callback contract: answering keeps its shape; authoring gets its own entry point

**Acceptance criteria:**
- [x] Authoring view lists every generated question with editable expected answer and alternatives
- [x] Saving persists the edited quiz; taking it afterwards scores against the edited expectations
- [x] Answering inputs never contain expected answers in DOM or storage before save
- [x] Unedited quizzes behave exactly as before
- [x] `node --test` green

**Out of scope:**
- LLM-generated or hand-written question banks
- Changing cloze generation heuristics (see ticket 04)
- Sharing quizzes between texts

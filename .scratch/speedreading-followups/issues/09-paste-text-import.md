## Agent Brief

**Category:** enhancement
**Summary:** Add paste-to-import so clipboard text becomes a library text through the same ingest pipeline as files.

**Current behavior:**
Texts enter the library only via the file picker (plain-text and EPUB files). A reader with an article on the clipboard must save a file first.

**Desired behavior:**
The library offers a paste box (textarea + import button) that takes pasted text, runs it through the same normalize/chapterize pipeline as file imports, and creates an identical text record (titled from the first line or a timestamped default). Empty or whitespace-only pastes are rejected with a readable message. Everything downstream — playback, quiz, sessions, export — treats pasted texts like file imports.

**Key interfaces:**
- The ingest pipeline's text normalization and chapterization: reused for pasted strings
- The text record shape and library list rendering: unchanged; pasted texts are indistinguishable downstream
- The existing import error surface: reused for the empty-paste message

**Acceptance criteria:**
- [x] Pasted article imports and appears in the library with correct word count
- [x] Empty paste rejected readably, nothing stored
- [x] Pasted text plays, quizzes, records sessions, and exports like a file import
- [x] `node --test` green

**Out of scope:**
- URL fetching or article scraping (local-only posture, ADR-10)
- Clipboard-read permission automation (explicit paste action only)
- Rich-text/HTML paste handling (plain text in, same as files)

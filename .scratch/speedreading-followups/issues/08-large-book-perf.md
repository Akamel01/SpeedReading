## Agent Brief

**Category:** enhancement
**Summary:** Measure tokenize + chunk time and memory on a 130k-word novel in Node and in-browser; fix only on measured miss.

**Current behavior:**
A full-length public-domain novel imports correctly (title, chapters, word count verified in Node and in-browser), but nobody measured how long tokenization and chunking take or how much memory the chunk array holds. Playback renders one chunk at a time, so runtime rendering is not the risk — import-time processing is.

**Desired behavior:**
A script measures wall time and heap for tokenize + chunk over the full novel text in Node, plus an in-browser import timing via the existing walkthrough harness. The numbers and a budget judgment land in the ticket/evidence log. If the import misses the budget (sluggish UI, multi-second block), the fix (e.g. chunked processing, lazy chapter tokenization) lands with before/after numbers; if it passes, no code changes.

**Key interfaces:**
- The tokenizer/chunker contract (tokens with trails, chunk policy): measured, not changed unless the budget misses
- The ingest pipeline returning chapter records: the import path under measurement

**Acceptance criteria:**
- [x] Node timing + heap numbers recorded for the 130k-word text
- [x] In-browser import timing recorded
- [x] Budget verdict recorded; fix with before/after numbers OR explicit no-change verdict
- [x] `node --test` green

**Out of scope:**
- Virtualized rendering or worker threads without a measured miss
- Changing chunk policy or storage design

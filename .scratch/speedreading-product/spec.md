# Spec — speedreading-product

Objective (user mission, 2026-09-23): transform SpeedReading from a functional prototype into a polished, enterprise-quality speed-reading training product. Not a restyle: reconsider IA, interaction model, visual hierarchy, states, navigation, feedback loops, gamification.

## Requirement digest (from the mission brief; sections cited)

- **Audit first** (§1): inspect repo + run app; baseline functionality, UX flows, visual system, state, persistence, weaknesses, reusable parts, constraints, test coverage. Never remove working functionality.
- **Target state** (§2–3): spec covering IA, navigation, page hierarchy, design system, component system, state architecture, session model, gamification model, persistence, animation, responsive, a11y, testing, performance, extensibility. Journey: Library → prepare/configure → Player → Quiz → award → Session summary → Dashboard → progression. First-class states include first-use, empty/populated library, importing/parsing/failed import, ready/active/paused/completed session, quiz + completed, achievement unlocked, level-up, streak update, returning user, no recent activity, corrupted data, unsupported content, interrupted/restored session.
- **Design system** (§4): tokens for bg/surfaces/elevated/borders/text hierarchy/muted/accent/success/warning/error/info/XP/rarity; type, spacing, radius, elevation, icon sizes, control heights, container widths, breakpoints, focus, motion timings, easing. Strong hierarchy, restrained gradients, quality cards, deliberate whitespace, meaningful status, premium controls, polished empty states, tactile interactions. Ban: rounded-card-everything, gradient spam, noise, gratuitous glassmorphism, excessive shadow, childish/neon gamification, giant empty areas, arbitrary decoration.
- **Responsive** (§5): intentional layouts at 320/375/430/768/1024/1280/1440/1920/ultrawide; nav collapse, dense controls, charts, tables, dialog sizing, touch targets, overflow, viewport height; reading mode prioritizes reading.
- **Library** (§6): content workspace — header, search, filter, sort, recent, favorites, reading progress, completion, estimated time, word count, last session, mastery; import surface with drag-drop, progress, success animation, invalid feedback, duplicate detection, parsing failure, recovery, supported-format messaging. Empty states designed.
- **Player** (§7): focused training environment — speed, WPM, progress, elapsed/remaining, section, pause/resume/restart/skip, modes, typography, distraction-free, keyboard+touch, session goal, live indicators; progressive disclosure; polished transitions for start/speed change/pause/resume/finish/mode switch.
- **Quiz** (§8): part of the training loop — progression, selection, feedback, score, comprehension, completion, review; states unanswered/selected/correct/incorrect/skipped/completed; seamless Player→Quiz transition.
- **Gamification** (§9–11, 16–19): primary feature, coherent progression economy. Domain concepts: profile, XP, level, streak, session score, WPM record, comprehension score, achievement + progress, challenge, daily/weekly goal, badge, reward, personal record, milestone, activity event. Reward desirable behaviors, not time. XP sources listed (session, quiz, WPM target, comprehension target, PR, streak, challenge, words, session count, consistency, return, milestone). Prevent farming, duplicate/double awards, inflated stats from replay/refresh. Loop: goal→train→measure→reward→progress→unlock→next goal; completion flow: metrics→quiz→score→XP→records→streak→achievements→level→rewards→celebration→summary→next goal. Prioritize the most meaningful feedback, not everything at once.
- **Trophy UI** (§10): use Trophy patterns where they genuinely help (XP, levels, achievement collection/unlock, streaks, progression, personal history); do not look like an unmodified Trophy demo; no fabricated social leaderboard — personal records/history/PRs only; data model extensible for future multi-user.
- **Animation** (§12): deliberate motion system communicating cause/effect, state, progression, reward, hierarchy, attention. Patterns for nav, card entrance, hover, press, focus, progress, XP gain, level-up, unlock, streak, quiz feedback, completion, dialogs, list changes, import, loading. Professional only; `prefers-reduced-motion` removes/reduces non-essential motion without breaking function. Do not animate everything.
- **Persistence** (§13): survive refresh/close/restart/errors. Persist library, reading progress, sessions, WPM history, quiz results, XP, levels, streak, achievements + progress, records, daily/weekly goals, settings, active session state, UI prefs. IndexedDB-class storage; versioned schema, migrations, corruption handling, safe defaults, atomic-ish updates, serialization validation, duplicate-event protection. Infrastructure, not convenience.
- **Event architecture** (§14): user action → domain event → state update → gamification engine → persistence → UI feedback; deterministic testable engine; reward logic not scattered in view code; views render state and dispatch actions.
- **Dashboard** (§15): performance center — current/best/avg WPM, comprehension, words read, sessions, streak + longest, XP, level + progress, recent achievements, PRs, recent sessions, trend, goals, recommendations. Hierarchy: primary performance → current progression → recent activity → achievements → long-term trends. Readable charts, no clutter.
- **Achievements** (§16): id, title, description, category, rarity, requirements, progress, unlock timestamp, icon/badge, hidden/visible. Testable rules. Examples include first session/quiz, 10/25/100 sessions, 1M words, WPM target, comprehension milestone, PR, 3/7/30-day streaks, sustained improvement, consistency.
- **Challenges** (§17): daily/weekly, optional; deterministic, timezone-aware resets; never dependent on UI being open.
- **Records** (§18): highest WPM, best comprehension, best combined, longest session, longest streak, most words/day, most sessions/day, best per mode; subtle recognition.
- **Session summary** (§19): WPM, comprehension, words, duration, score, XP, streak status, records broken, achievements, level progress, comparison to own baseline; answers "what did I accomplish / improve / train next".
- **A11y** (§20): WCAG 2.2 AA — keyboard, focus, semantics, ARIA, contrast, labels, SR, dialogs, toasts, errors, reduced motion, touch targets, zoom/reflow, no traps; usable at enlarged font sizes.
- **Browsers** (§21): Chrome/Edge/Safari/Firefox, desktop+mobile, touch/mouse/keyboard; avoid unnecessary browser-specific APIs; graceful fallback.
- **Performance** (§22): bundle, splitting (n/a — no build), dashboard/chart rendering, large libraries, animations, imports, persistence, long docs; no heavyweight deps; measure, don't assume.
- **Security/data integrity** (§23): validate imported content, safe URLs, sanitize rendered text, no unsafe HTML, validate persisted data, reject malformed JSON, handle corruption, prevent reward duplication. All imported content untrusted.
- **Import/export** (§24): versioned export schema preserving library/settings/progress/achievements/XP/streak/sessions/records/goals; import validates, migrates old versions, rejects malformed with useful errors, no destructive overwrite without confirmation; full backup/recovery.
- **UX states** (§25): every component: default/hover/focus/active/disabled/loading/success/warning/error/empty/partial/completed; no browser-native-looking controls where a product-level interaction is expected.
- **Grill the design** (§26): attack every major UX decision (comprehension, cognitive load, next action, training reinforcement, meaningful gamification, visual excess, animation usefulness, mobile, a11y, friction, complexity vs value). Replace weak ideas.
- **Implementation strategy** (§27): phases A audit, B target architecture + UX/design spec, C design system + shell, D library, E player, F quiz, G gamification engine, H persistence, I dashboard, J animations/reward moments, K a11y + responsive, L testing + hardening, M final polish. After each phase: build, test, run, inspect, fix, re-test. No unverified accumulation.
- **Testing** (§28): unit (XP, levels, achievements, streak, challenges, records, session/quiz scoring, date/timezone, serialization, import/export, migrations); integration (reading→quiz→reward→XP→level→achievement→streak; refresh/close persistence; export/import recovery); E2E journey (new user→import→read→quiz→XP→unlock→refresh→state survives→close/reopen→survives→export→clear→import→recovered); a11y automated + manual keyboard; responsive viewports; visual regression baselines where tooling allows.
- **Invariants** (§29): XP never decreases absent explicit reset; no double award per event; completed sessions immutable/versioned; streak once per calendar day; achievements unlock once; imported data cannot produce invalid state; level always corresponds to XP; progress in bounds; quiz scores in range; persisted state migratable or safely rejected.
- **Validation loop** (§30) + **exit conditions** (§31): the mission's full checklist; stop only when further changes would provide no material improvement.
- **Deliverable** (§32): architecture/UX/gamification/persistence/animation/responsive/a11y/test/perf summaries, limitations, files changed, validation commands — report what was implemented and verified.

## Hard constraints (repo truth)

- ADR-1: no build, no framework, zero runtime deps, vanilla ESM under `src/`. React/shadcn/Tailwind are NOT installed; Trophy is grammar-only.
- ADR-2/6: IndexedDB via `src/lib/store.js`; `node --test` for pure libs; DOM/IDB via CDP harnesses.
- ADR-7: dual-mode presentation, a11y wins ties. ADR-10: zero network after load. ADR-18: no speed-promise copy. ADR-19: `tokens.css` `:root`-only; `app.css` consumes.
- Single user now; no accounts/backend. Architecture must allow multi-user/cloud later without rewrite.
- Do not remove working functionality.

## Acceptance

Mission §31 exit conditions, condensed: all existing functionality works; new flows end-to-end; library/player/quiz/dashboard redesigned; gamification deterministic (XP/levels/achievements/streaks/challenges/records/summaries); persistence survives refresh+close; export/import restores complete state; versioned storage + migrations; loading/error/empty states; coherent motion + reduced motion; a11y validated; responsive validated; cross-browser validated; import security addressed; performance acceptable; unit/integration/E2E green; no critical console errors or obvious visual defects; gamification logic separated from presentation; extensible architecture; no unnecessary dependencies; documented.
